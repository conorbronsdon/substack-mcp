# Draft tag assignment

`update_draft_tags` accepts a positive `draft_id`, UUID arrays `add` and `remove` (up to 20 unique IDs each, disjoint), and `dry_run` (default `true`). At least one tag ID is required. Use `list_publication_tags` to find IDs, including hidden tags. Hidden tags can be assigned; the result marks them. With multiple configured publications, select `publication` explicitly.

Results cover every requested ID, so there is no pagination or continuation. An unknown ID is refused before writing; its name and hidden status are `null`, not guessed.

The tool reads publication context, all tag definitions, the draft and current associations (four reads). A dry run returns intended actions with zero writes. A live call rechecks unpublished, unscheduled draft state immediately before the first write, then sends sequential adds followed by removes, at most once per tag. After writing, it reads the draft state and associations once each (up to seven reads total). It sends no automatic retry. A 400 is reported as `rejected`; 401, 403 or 429 stops further writes as `retryable`; other failures stop as `unknown`. A confirmed write is `verified` only if readback shows the requested association state and the post-write draft check still finds an unpublished, unscheduled draft. This observation does not prove which request caused the state. If an `unknown` or `retryable` write's desired state appears in readback, it becomes `observed_after_unconfirmed_write`; it is never `verified`. If readback does not show the desired state, it keeps its original outcome. Inspect `unverified`, `unknown`, `retryable`, and `observed_after_unconfirmed_write` outcomes in Substack before another write.

Published, scheduled, sent, unreadable or cross-publication drafts are refused before writing. A scheduled draft has error code `draft_scheduled`. Unknown tag IDs are refused. `draft_state_after` is `not_checked` when no writes were sent, `unpublished` when the final draft check passed, `changed` when it found a published or scheduled state, or `unverifiable` when that state could not be read or validated. For `changed` and `unverifiable`, no row is upgraded to `verified`; the note warns that tags may now be on a published or scheduled post. Tag assignment on a draft may become public when you later publish it through Substack. Separate reads and writes are not atomic; publication can occur after the final check. The attach and detach request shapes (bodyless `POST` and `DELETE` to `/api/v1/post/{post_id}/tag/{tag_id}`, with a publish-post Referer) come from public client sources and await the maintainer's live check on a disposable draft.
